# EXP-024 连续窗口确认复算

固定比较 EXP-021 已闭合的 Linear A 保存概率：A 为 max≥0.5；B 为同一 clean run 内目标起点相差 1.5±0.000001 秒的两个时间相邻、物理元组相异窗口均≥0.5。B 分数为全部合法对最小概率的最大值。短尾、缺窗和 run 断点均不能凑确认；无合法对时 B 分数、判决为 `null`，覆盖门槛失败。

入口只使用 Python 标准库，只读两个 A 角色的 CSV、闭合回执、固定 plan、sources 和原 dense 网格。按 `<16i` 物理元组 SHA 与目标时间、实际首末帧时间同时绑定，不重建网格、不重新验收媒体、不读取视频或权重，不访问网络、不训练或运行模型。新输入 SHA 绑定到旧闭合记录和原 plan 的指纹；A 的所有视频 max、数量、标签、场次和角色混淆必须完全复现。

在仓库根目录运行唯一微型夹具：

```powershell
python experiments/tests/test_confirmation_replay.py
```

代码定点审查通过后，才能运行真实复算：

```powershell
python experiments/runspecs/EXP-024/replay.py
```

默认输出 `data/results/exp024/confirmation-s7-dev-v1/`。已存在时拒绝覆盖；必要时 `--out data/results/exp024/<新run_id>`，仍只允许 EXP024 的直接子目录。输出包括逐角色视频 CSV、四负场次 CSV、`result.json` 和运行源码副本；JSON 保存输入及源码 SHA、命令、环境、固定规则、全部正视频的两规则首次触发时刻及相对等待分布／最大值、门槛判定。CSV 的无触发或覆盖不足字段使用字面值 `null`，不能读作 0。

首次触发时刻采用触发窗实际最后帧时间，B 使用第二窗。两者相减仅表示相对输出等待，并非相对泥石流真实起点的识别延迟。全部 47 次角色出现须有合法对；共享视频跨角色只要仍有一个 FP，就不计完全修复。负场次 FPR 依次先对同视频跨角色平均，再按场次内视频平均，最后四场次宏平均。

本复算是由已查看数据启发的自适应开发观察；机器门槛通过仅表示值得进一步完整验证，不能修改 EXP-021 的原判定，也不能宣布输出等待已满足应用需求。完整规格见 `docs/process/experiments/EXP-024.md`。
