# 实验Git归档规范

用户于2026-11-10要求建立公有实验仓库，每个实验一个分支，只发布最终有效版本。仓库地址及实际发布提交以`data/metadata/experiment-archive/publication.json`为准。

当前发布范围：用户指定EXP-008采用已完成的跨场景三项MIL版本`mil-v2-150-strict-scene`；原场次`full`版本留在Git历史中。其他实验须等用户逐项指定，不因已整理好本地分支就自动上传，禁止`push --all`。公有`main`已包含共享代码和元信息，但公开实验索引仅列已确认发布的编号。

## 仓库内容

分支README的内容、排版和复现步骤统一遵守[实验README内容与复现说明规范](experiment-readme-standard.md)。该规范面向首次接触仓库的读者；完善说明不自动授权执行训练。

- `main`保存实验总索引和共享代码；`codex/EXP-NNN`保存该实验的说明、数据使用方式、结果及证据清单。未训练草案明确标记，不混充已完成成果。
- 代码保持项目内相对路径；共享模块只维护一份。分支说明列出实验入口、工具、架构、学习策略、数据成员/标签/采样/划分规则及结果位置。
- “每实验一分支”是Git逻辑组织，不是在本地复制一套目录。现役代码、数据和结果仍只保留原有正本；发布映射用文件清单、Git tree/index或对象构建实现。如工具需要临时导出目录，只保留一份短期工作区，使用完成即清理；不保留逐实验副本或多版导出包。Git对象库与发布凭据可保留，不将其伪称为零额外占用。
- 每分支README直接作为完整实验报告，集中说明数据使用、模型结构、学习与损失、训练结果和结论；与论文的差异在同一报告交代。机器清单作证据附件，不让读者在多份入口间拼接正文。EXP-008当前只报告`mil-v2-150-strict-scene`的三项MIL配置，不混入BCE对照；strict是输入筛选，不是片段BCE训练。
- 发布最终有效run及其必要的成功续跑组件，不发布作废成绩、失败训练、冒烟成绩或撤回版本。阴性实验结果只要执行有效仍然保留。
- 元信息包括来源说明、成员ID、标签、冻结划分、采样计划、环境和指纹；不包含视频、图像、像素缓存或特征张量。较大的逐窗口派生表可只登记来源和哈希，须说明省略。
- 用户允许上传可复算权重：保存权重到预测/指标的核对及SHA256，小权重随分支，大权重用Release等合适载体，不将优化器、重复last或未验证权重冒充可复现模型。原视频到特征重建、权重推理和完整重训是不同核验范围，分别说明。
- 指标、预测、选轮记录和必要日志保留原值。缺失的原始报告、历史执行源码或独立测试明确标为缺口；当前源码快照不能冒称历史执行源码。
- 结果陈述带原标签版本、评价单位、选轮和划分限制。整理归档不使开发成绩变成独立测试成绩。

## 发布与更新

1. 按用户白名单建立原文件到公开Git路径的映射计划，生成源文件/发布字节SHA256和省略清单。优先使用`experiments/tools/publish_archive_objects.py`直接构建Git对象，不落地重复文件树；旧`export_experiment_archive.py`的全量导出不是当前默认流程。
2. 核对覆盖本轮获准发布的实验，不含未授权原始媒体、特征或凭据；权重按授权及核验范围发布。说明须与实际结果相符，无原始证据的数字只能标为文档记录，不能写成已复算结果。
3. 通过独立发布Git的索引和对象提交并推送，不切换现役工作树，不混入其他任务改动，不推送含大文件的旧历史。更新沿用远端历史，正常新增提交，禁止默认强推或重建孤立历史覆盖旧分支。
4. 保留发布清单、远端地址及每分支提交；推送后核对远端分支。仓库创建和本轮上传已有用户授权；不因此取得训练、付费或发布其他材料的授权。
5. 更新实验卡或结果后同步对应实验分支及总索引。当前开发Git与发布仓库是不同用途，不能直接将开发`main`推送覆盖发布`main`。

工作区目录职责见[工作区组织规范](workspace-layout.md)。归档不改变本地原run、标签、现役训练输入或学习手册。
