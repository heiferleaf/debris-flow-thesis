# 实验README内容与复现说明规范

## 读者与目标

假定读者第一次接触仓库、没有看过聊天记录，但已获得明确指定的实验数据。仅凭分支README和代码，应能理解实验，并按完整步骤复现所报告的结果。README就是实验报告，机器清单和日志作为证据附件，不代替正文。

文档整理不自动授权实际复跑、数据重建、下载大文件、租卡或付费。用户只要求完善说明时，只做文档、配置说明和静态检查。

## 内容必须自足

1. **问题与方法**：说明研究问题、模型输入与输出；首次出现时解释MIL、MLP等术语。
2. **数据与使用**：写清来源、总量、正负数量与标签含义、实际训练输入、取帧/窗口/特征构建、剔除规则及监督粒度。视频标签、片段标签和输出之间的关系要明确。
3. **划分与训练**：写清分组单位、各侧数量、交叉验证、选轮/阈值依据、优化器、学习率、轮数、种子和样本组织。不用“沿用上次”“按现役协议”代替实际设置。
4. **模型与损失**：结构图说明数据流；表格说明模块、维度和训练状态；公式先定义符号，再解释目标。与参考论文的差异集中说明。
5. **结果与分析**：报告最终有效版本的原始数值、评价单位和聚合方式，给出逐折结果、混淆矩阵及必要分类指标；区分观察和推断，保留影响结论的选轮和测试范围限制。
6. **复现步骤**：指定代码分支、环境版本、数据包内容和目录结构；按准备数据、训练、评价、核对结果给出可复制命令及预期输出。原视频、冻结片段帧和特征缓存是不同输入条件，不能把缺失处理中间件藏在本机路径里。
7. **一致性与证据**：给出参考结果、成员/标签版本、可用指纹及比较精度。不能仅凭AUC相同宣称预测一致，不能把权重推理核对说成原片重建或完整重训已验证。历史缺失信息明确标出，不猜补。

## 写作与排版

- 正文只解释该实验。其他版本的strict/loose、文件读取开关、纠错过程等，若非理解本实验所必需，不放入主叙事。
- 先说明“训练特征”“视频标签”等概念，再给文件名。不要用“不读取某文件、不启用某掩码”代替数据如何使用的说明。
- 使用GitHub原生Markdown：数据、划分、结构参数、训练设置和结果用表格；模型数据流优先用Mermaid；数学公式用独立LaTeX块并解释符号。
- 一节回答一个问题，使用完整语句，避免流水清单、重复免责声明和依赖聊天背景的对比。数字、单位及小数位一致。
- 核心认知和执行步骤保留在README，较大的代码/文件索引可放折叠附录。读者不应通过拼接多份说明才能理解实验。

## 交付检查

按陌生读者顺序通读，静态核对命令、路径、参数和数值是否对应实际代码与参考结果；检查GitHub表格、Mermaid及公式语法。文档修改不触发训练或大规模数据核验。只更新用户选定的分支，完成后核对远端README与本地版本一致。
