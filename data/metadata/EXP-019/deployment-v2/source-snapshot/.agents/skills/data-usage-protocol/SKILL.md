# 双模式数据使用协议（每次训练必读）

**本 skill 是训练数据使用方式的硬约束清单**，正本 = `docs/process/experiments/EXP-006-数据使用方案.md`（叶海峰 2026-09-15 /goal 授权设计并试点执行）。改动任何一条：先改正本注明日期，再改代码，不擅自定。

## 启动前核对

写训练循环或重跑训练前，逐条核对下列约束在代码与清单里成立；核对结果写进汇报。

## 硬约束（任何模式、任何实验都不得违反）

1. **同场次不 split（协议一/二）**：划分原子 = 场次组 = `d|{地址名}|{日期}`（东川机位名；v4/v5 机位 = 视频**右下角地址水印名**，2026-09-24 叶海峰确认逐视频映射，D 编号只存 site_code 列不当分组依据）。协议一/二下同组所有段、所有窗口、所有帧强制同侧，不得把同场次拆到两边。外部 v2 多场景拼接素材**每段一组**（段=独立场景）；v3 DeFlow **每视频一组**（两个视频=两个场景，2026-09-24 叶海峰指正）。**协议三「同场次混分参照」（2026-10-04 叶海峰定，research-auditor 决策复核通过）**：划分原子 = 单位本身（EXP-008 线 = 整条视频；EXP-006 线 = 段），按标签分层随机 k 折、不施加组约束，同场次可拆到两边；成绩**只作上限参照**（i.i.d. split，量「组约束付出了多少」），凡引用必须带脚注「同场次混分参照，含场次内画面相似性，非泛化成绩」，不得用于任何泛化/部署主张；独立正本落 `data/metadata/splits/`（如 `EXP-008-units-iid-folds.json`），一次生成落盘后冻结，与协议一折分开。
2. **同场次同地点多个视频合并**：一场次被拆成多个视频文件时，它们归同一组；跨源合并（v4/v5）的前提是**同地址名**（同场景）。D12 因云台预置位不同，video4=塔吊下方、video5=塔吊下游，是两个场景两个组，不得按 D 编号捆组（2026-09-24 发现）。
3. **同场景不 split（严格形态）**：主口径按「场次组」划分，同场次绝不拆；更严格的整场景/整源留出（如 LOSO）**只作数据充分性检查，不作泛化能力成绩**——抽走样本量占主导的源（东川）后训练集所剩无几且几乎无正样本，考出来的是「缺这个源练不成模型」的数据结论，不得表述为「模型跨源泛化差」。（叶海峰 2026-09-24 指正）**默认停跑**（叶海峰 2026-09-24 追加：训练集几乎无正样本时训出的模型本身无效，属稻草人设置；数据依赖论证用场景级成绩承担，需要引用时 --sufficiency-check 单独跑）。
4. **监督窗口不跨标注段**：训练及用于选轮的监督片段验证窗口须完整位于同一pos/neg标注段，不为跨类别转换的混合窗口赋单一片段真值。**整视频推理**按标签无关的质量规则和固定时间网格取窗，允许原录像内真实类别转换，不读pos/neg边界作推理掩码，仅按视频标签评价。两者不能混报；剪辑、灰坏帧、PTS倒步/空洞仍须排除，不拼接禁区两侧（2026-10-30范围澄清，先正本后实现）。
5. **段内帧上限**：每段每轮最多 64 帧。EXP-006 旧时序管线先取最多 64 帧，再以步长 8 在这些帧上形成最多 8 个相互重叠的 16 帧窗口；这个“8 窗口”不等于允许 8 个各自独立抽取的 16 帧片段。EXP-008/009/014 一类现有片段若彼此分散取帧，按 16 帧/片段计，一个段每轮最多 4 个片段（4×16=64）；超过时段内均匀取。短段补帧（<16 帧 linspace 重复索引）仍按旧时序管线执行。
6. **段间等权**：贡献按段计票，不按帧计——相邻帧高度相似，按帧数算等于让少数长段说了算。**EXP-016例外（2026-10-30，决策复核及用户对话确认，正本已先更新）**：贡献上限按视频×类别共享，每组每轮最多4个不同16帧输入，同类标注行及cut两侧不分别增额，各原区间合法位置跨轮轮换；单窗不跨原标签段/质量禁区，单原段仍最多64帧。不是严格段/视频/场次等权，不凑48；旧实验不追改。初筛未完成第10条须明示。
   **EXP-018沿用（2026-11-01）**：依据用户20元内推进科研、数据搜集与实际验证的明确目标授权，原样复用EXP-016 training-plan-v2的配额和输入；仅在相同片段曝光/批次下比较BCE及两种排序关系，附加排序按80对等权而非场次等权。正本已先补记；当时不扩展到EXP-017、不回写旧run，按当时快照第10条仍未完成。
   **EXP-017后续阶段沿用（2026-11-01，EXP-018完成后）**：依据同一20元目标授权及Astra规划／Sol路线复核，正本先补记后沿用视频×类别最多4窗的配额，仅用于普通RGB场次组评价；每次拟合的N/P只取其训练窗口。内层固定验证选E，外层从公开预训练重新初始化并训练恰好E轮，外折不参与选轮。须补齐150条角色无关候选及实际输入验收，不套用旧119/31、504/136编排；不称严格等权、未见机位或独立测试，不改变旧run或EXP-018晋级条件。阶段≤7元计入已有20元，signed_by留空，启动仍须代码、输入、协议及预算守门。
   **EXP-019开发排列对照沿用（2026-11-01）**：在同一20元授权内，经Astra规划及Sol规格审查，正本先补记后复用EXP-018普通A的119/31、504/136和20轮批次；两支同帧集合／曝光／初始化，只对模型T轴施加真实顺序或固定置换，物理bank/PTS/QC仍规范。窗口键为256中间件SHA＋规范16索引，监督与dense共用、不读标签／role／评分，不消耗训练随机流。第6条共享配额例外不变，第10条仅开发小试；≤4元计入20元、signed_by空，启动另须实际代码／输入／测速门禁，不追改旧run。
7. **权重倒数关系**：损失按窗口数反比加权，pos_weight = 负样本数/正样本数；正段少时不加权会学成「全判负」。
8. **视频/图片配比**：多帧时序模型只用视频段；单帧模型混入独立图片库时 1:1 起步再调。
9. **零头不入清单**（叶海峰 2026-09-24 定）：未标注的隐式区域若只含 ≤1 帧（审计台显示粒度以下的零头，典型为视频末帧落在最后一条标注末端之后的舍入缝隙——审计端点是整数秒、帧时间戳带小数），**不生成隐式负段，直接从清单剔除**；人工标注过的段一字不动；剩余 ≥2 秒、含 ≥2 帧的未标区域仍按「未标=隐式负」既有约定生成。适用所有数据源，后续新数据集一律如此处理。
10. **分阶段验证，结论对应隔离范围**（2026-11-01用户授权助手评估，Sol决策复核通过，正本已同步）：开发初筛可用预先冻结、场次隔离的单划分，不报告正式泛化成绩；保留方法与基线正式比较须预登记协议一场次分组交叉验证，选轮、阈值和超参数仅在训练侧确定。声称适应未见机位时，另须协议二整机位隔离验证，场景组按地址名严格同名合并，先核各侧两类与组覆盖。折数由数据覆盖决定，不强制每个阶段都双五折；窗口数用于分层，组不可拆，实际组／视频／窗口和类别规模须报告，划分及seed落盘`data/metadata/splits/`。最终独立测试单独冻结，不用于选方法或调参。机位×日期组不自动等于独立灾害事件。旧EXP-016／018按其当时快照解释，不回写为已完成双协议，也不更改旧晋级条件。

## 两种模式

- **单帧模式**（独立图片库）：防泄题单元 = pHash 簇（每簇 ≤8 张的等价物）/同机位场次；簇内同侧。
- **时序模式**（视频段）：如上表硬约束 1–7；划分之外再加「段内 ≤64 帧」与「类权重」两条。
