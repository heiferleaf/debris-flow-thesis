# 双模式数据使用方案（采样准则，叶海峰 2026-09-15 /goal 授权设计并试点执行）

问题背景：东川 5.6 万正帧里相邻帧高度相似（2s/帧），**按帧数算权重等于让少数长段落说了算**；外部场景段几十帧一段，量级完全不对等。四条准则解决"训练时一帧值多少票"。

## 四条准则

| # | 准则 | 一句话理由 |
| --- | --- | --- |
| 1 | **段内均匀子采样**：每段每轮最多取 64 帧（或等价地：窗口化时每段最多 8 个窗口） | 相邻帧信息冗余，60 帧和 600 帧的段落贡献几乎相同 |
| 2 | **段间等权**：票数按段计，不按帧计 | 划分原子是段（机位×场次/场景段），模型要学的是"这段是不是泥石流"，不是"这段有多长" |
| 3 | **视频/图片配比**：多帧模型只用视频段；单帧模型混入图片数据时按 1:1 起步再调 | 图片库（1.4 万张）和视频段量级差异大，防一边倒 |
| 4 | **类权重**：损失按窗口数反比加权（pos_weight=负/正） | 正段少（试点 ~25+3），不加权会学成"全部判成没有泥石流" |

**2026-10-28 对准则 1 的适用范围作解释，不改变 64 帧上限：** 旧 EXP-006 时序管线在同一段先取最多 64 帧，再用步长 8 形成最多 8 个相互重叠的 16 帧窗口，所以“8 窗口”仍来自这 64 帧。EXP-008/009/014 一类现有片段是分别从视频不同位置抽取的 16 帧，若在一个标注段内取 8 个，会接触最多 128 帧；按本准则在该形态下只能每段每轮最多取 4 个片段。下一轮 EXP-015 草案按这一解释设计；尚未生成新抽取清单或训练。

**2026-10-30，EXP-016对准则2的经审查修订，用户对话确认：** 本卡监督训练与固定片段验证将贡献上限归于“视频×类别”，每轮每组最多4个不同的16帧输入；同类人工标注行和cut两侧共享这一上限，避免标注碎分增加训练份额。不限制标注区间数量，各原区间内合法位置跨轮轮换；任何单个窗口仍完整处于原标签段及质量有效区，不跨cut、不拼接，单原段每轮仍不超过64帧。该设定控制取样贡献，不宣称每段、每视频或每场次梯度严格等权，不要求凑48。其余实验沿用各自冻结协议，本修订不回写历史成绩。EXP-016初筛仍未完成双协议交叉验证，不宣称全部遵循第10条。

## 零头不入清单（2026-09-24 叶海峰定）

未标注的隐式区域若只含 ≤1 帧（审计台显示粒度以下的零头，典型为视频末帧落在最后一条标注末端之后的舍入缝隙——审计端点写整数秒、帧时间戳带小数，差 0.02–0.47 秒；东川全清单 72 例，叶海峰确认审计台未显示该零头区域），不生成隐式负段，直接从清单剔除。人工标注过的段一字不动；剩余 ≥2 秒、含 ≥2 帧的未标区域仍按「未标=隐式负」既有约定生成。适用所有数据源，后续新数据集一律如此处理。落地：`build_segment_manifest.py` 段生成层过滤。

## 分组口径修正与双协议（2026-09-24 叶海峰定）

三处分组错误由叶海峰指出并纠正，同日落实：

1. **v4/v5 机位以视频右下角地址水印为准**，D 编号只存 mapping 的 site_code 列。映射（子代理逐帧读图、叶海峰确认）：D02→1号塔广角、D05→多照沟（门前多照汇口）、D13→塔吊上游、D15→1号塔下游；**D12 两批预置位不同**：video4→塔吊下方、video5→塔吊下游，拆为两个场景。地址名与 v1 场景**严格同名合并**（塔吊上游、塔吊下游并入 v1 对应场景组）。
2. **v2 每段一组**（段=独立场景，拼接视频的文件边界不是物理独立单元）；**v3 每视频一组**（两个视频=两个场景）。
3. **双协议分别交叉验证**：协议一场次组 `group_id`=`d|{地址名}|{日期}`；协议二场景组 `scene_group`=`s|{地址名}`（同机位跨日期整组同侧）。两列成绩分别回答「下一次泥石流能不能认出」（协议一）与「没见过的机位能不能认出」（协议二）。

**协议三「同场次混分参照」（2026-10-04 叶海峰定，research-auditor 决策复核通过）**：划分原子 = 单条样本本身（EXP-008 线 = 一条视频；EXP-006 线 = 一个段），按标签分层随机 k 折、不施加组约束，同场次可拆到两边。定位 = i.i.d. 上限参照：与协议一之差 = 场次记忆/画面相似性成分的实测估计，与协议二构成「同场次混分 → 跨场次 → 跨机位」泛化阶梯。凡引用协议三成绩必须带脚注「同场次混分参照，含场次内画面相似性，非泛化成绩」，不得用于任何泛化/部署主张；独立正本落 `data/metadata/splits/`，一次生成落盘后冻结，与协议一折分开（协议一/二的组约束条款不变，仅协议三豁免）。

折划分配套修正：分层目标由段数改为**窗口数**（窗口才是训练单元）；组不可拆，折间规模做不到绝对公平，每折考卷规模（组/段/窗/帧）如实入报告；折划分清单落盘 `experiments/splits/EXP-006-{session|scene}-folds.json` 并过 `split_checks` 校验。「留出东川」类整源留出重新定位为**数据充分性检查**，不作泛化成绩（抽走占主导源后训练集骤减，成绩接近随机是设计使然）。

## 与划分的关系

- 划分（train/val/test 谁进哪边）是**组级**的：协议一场次组（机位×日期）/ 协议二场景组（地址名）；外部 v2 场景段、v3 视频各自成组。采样（每段取多少）是**组内**的。两者独立——先划组，再在训练组内做准则 1、2。
- **需要片段真值的监督窗口不跨标注段**：训练及用于选轮的监督片段验证窗口须完整位于同一pos/neg标注段，不能给跨类别转换的混合窗口强行赋单一片段标签。
- **2026-10-30范围澄清（决策复核通过）**：整视频推理按预登记、标签无关的质量检查与时间网格抽窗，允许窗口包含原录像中的真实正负转换；此类窗口不赋片段监督真值，只按视频标签评价。推理不得用pos/neg边界剔窗或救选明显正片段。剪辑、灰坏帧、时间戳倒步/空洞的质量约束仍适用，不能把删除区间两侧拼成连续片段。监督片段选轮指标和整视频指标分开报告。
- 训练损失按**窗口**逐条计算（`BCEWithLogitsLoss` 对 batch 内窗口等权），段间贡献比被「每段 ≤64 帧/8 窗」上限封顶在最多 8:1——准则 2 的段间等权是这个意义上的**近似**，不是严格等权（research-auditor 2026-09-24 补注；折分层按窗口数与之一致）。
