# EXP-008输入与时间轴核查

本核查针对150条冻结输入和原运行产物，不重新训练，不修改旧标签、片段或成绩。

## 核查结论

- 150条各48个片段、每片段16帧，共115,200张图全部可读取，均为256 × 256。
- 所选图像与历史QC均未低于灰度标准差20；检查历史逐帧QC共3,474,033行，其中110,894帧低于阈值，已选帧及其16帧安全边距没有触及这些低方差帧。这个指标用于筛查灰屏，不能证明所有类型的画质损伤都不存在。
- 7,200个候选片段中，6个有明显内部时间前跳。另一个最初被全片阈值报警的片段，其15个间隔均为0.25秒，是均匀较慢的采样，已从“内部跳跃”计数中移除。
- strict排除1-32的5个相关片段，但保留1-109的第46个片段。它不是该视频留出模型的最高分片段；移除后视频分数仍为0.4893850684。此项只验证评分敏感性，不衡量它对其他折拟合的影响。

## 代码原因与证据

**帧号相邻不保证时间连续。** 历史脚本用`start + 0…15`取相邻解码帧。若解码中间件本来缺了一段时间，帧号仍连续；灰度方差也可能正常，因此图像检查和数量检查发现不了时间缺口。

原开发仓库提交`cf08acaddc038f0989aea44c1767771faa023a05`中的`experiments/repro/exp008/build_units_v2.py`，其禁区合并包括cut、低方差帧和PTS倒步邻域，没有现在工作文件中的`pts_gap_zones`前跳排除。保存的6个片段证实，不能用后来新增的函数宣称历史抽帧已经经过此前跳检查。该提交是可检索的旧源码证据，不冒称完整历史执行环境快照。

**重复的秒数字符串不等于重复图片。** 定点复核1-27第1个片段，16张JPEG的哈希各不相同；重新读取中间件的整数PTS，时间基为1/10240。前两帧PTS分别为2575360和2575361，实际相差约0.000097656秒，但旧`showinfo`文本都显示为251.5秒。历史转码日志同时记录11,984条DTS单调性修正告警，说明既有文本精度损失，也有转码对时间戳的修正，不能只把这件事归结为图片重复或普通四舍五入。

`build_units_src256.py`只使用`-vsync 0`，未将原始整数PTS和时间基作为不可丢失的映射保存。其`probe_frames`解析`showinfo`的短格式`pts_time`，再次丢失了精度。因此，“中间件时间戳无条件等于原视频时间戳”的旧表述证据不足。1-32和1-109的秒级跳跃已通过中间件整数PTS直接确认，但缺口究竟在原始采集、源解码还是首次转码形成，尚缺同一段原片的可靠逐帧PTS对照，不能仅凭中间件确定。

此外，1-09现存坐标表为20,551行，抽帧QC及清单为20,550行；两表按同一帧号比较最大差8.52秒，所选片段位置最大差0.08秒。该坐标表不能冒称冻结抽帧坐标的字节级原件。原片段图像和缓存保留原样，后续制作必须冻结媒体、坐标表和QC的联合指纹。

## 对后续时间间隔实验的要求

1. 按目标秒数定义16个时刻，例如3秒输入为首帧到末帧相隔3秒，15个目标间隔各0.2秒；不以“取相邻16帧”或元数据fps代替。
2. 每片段保存目标时间、实际整数PTS/时间基、源帧号及逐点误差。重复帧号、反向时间或超过容差的匹配不能作为合法片段。
3. 不跨越真实解码缺口或cut；质量禁区、坐标和实际媒体须为同一版本。时间前跳和时间倒退都要处理。
4. `build_units_stride.py`用全片正间隔中位数估计fps，再取固定帧数步长，不能保证变帧率局部仍是0.5秒。它不应作为严格时间跨度单变量实验的依据。
5. 现有`pts_clip_sampling.nearest_window`已使用目标时间和逐点误差检查，比固定帧步长更适合；其输入时间轴仍须先核准。后续扩大到其他跨度时沿用同一匹配规则并明确容差，不混用两套取材机制。

上述是数据准备与实验解释要求，本次没有重建数据或启动训练。

## 结果的使用范围

五个已保存的跨场景MIL分类头均能从原特征复算出原预测和AUC；随机一组16帧重新计算特征，与缓存逐元素相同。没有发现凭空编造这些已复核分数或该组特征的证据。

本实验可作为旧标签、旧地点分组下的方法重实现和开发结果，指出三项MIL与最大值判定的局限。它不能单独支撑固定时间间隔有效、模型具备物理时序能力或已达到部署效果的结论，也不能把验证折选轮后的平均AUC当独立测试成绩。

机器证据位于`data/metadata/experiment-archive/`：`exp008-input-quality-20261110.json`、`exp008-precise-timestamps-20261110.json`、`exp008-scene-gap-sensitivity-20261110.json`及`feature-cache-spotcheck-20261110.json`。原视频到冻结帧的完整逐字节重建仍未完成验证；不通过覆盖旧文件来制造一致。
