# 训练数据加载适配器（设计，2026-09-16 叶海峰定方向）

> 背景：你以软件工程视角指出——训练代码为每个数据根裸写路径拼接（`cache_features.py` 里 `root = frames if 东川 else frames-scenes` 曾是反面教材），数据形式稍有改动就改加载代码，违背**开闭原则**；旧 data/ 下碎片目录（frames / frames-all / frames-extneg / frames-scenes 功能重复）已于 2026-09-16 收敛为新结构（初帧留 `data/process/video_frames/`，最终帧进 `data/final/video_windows/`）。
> 目标：**加载接口保持不变，各种实现可插拔（适配器模式）**；加载窗口数量、帧数量这类限制做成可配置策略，不在代码里写死。

## 一、加载模式只有两种（你的定调）

你说过：加载数据只有**加载单帧**和**加载连续帧**两种模式；至于连续帧来自原本图片集还是分帧得到，是数据源差异，不应暴露给训练代码。

```
                 ┌────────────────────────── 训练脚本（只依赖接口） ──────────────────────────┐
                 │  train() 只调用 adapter.load_*()，不了解 data/ 物理布局                        │
                 └───────▲───────────────────────▲───────────────────────────▲───────────┘
                         │ 统一加载接口（不变）        │                          │
                 ┌───────┴────────┐   ┌────────┴─────────┐   ┌────────────────┴───────────────┐
                 │ SingleFrameAdapter│ │ VideoWindowAdapter │  │  采样策略 (sampling policy)      │
                 │ 单帧：图片找回      │  │ 连续帧：段/窗口/帧   │  │  每段帧上限、窗口数、类权重、      │
                 │ 无需时间索引        │  │ 需时间索引+窗口滑    │  │  短段加密≥16帧 等——全部可配置      │
                 └───────┬────────┘   └────────┬─────────┘   └────────────────┴───────────────┘
                         │                     │
        data/raw (d1-4图片)           视频来源：初帧+分段标记(data/process/video_frames/videoN_segment/)、加密后最终帧(data/final/video_windows/videoN_segment/)，或直接源视频
```

**核心不变式**：训练脚本只见两件事——「输出单帧样本」或「输出连续帧窗口」，且每个样本带 (split, label, 段id)。数据源（图片集/东川拆帧/外部场景帧）与限制策略（每段几帧、每段几个窗）全部藏在适配器内部，改数据布局或改策略都不用动训练脚本。

**数据布局说明（2026-09-16 新结构）**：短段加密前的审计分段标记（`events.csv` / `extneg-scenes.csv`）与初步分帧同放 `data/process/video_frames/videoN_segment/`；`data/final/video_windows/videoN_segment/` 只放加密后最终帧与帧级标签清单；videoN→数据源映射（东川/网络/新增源）由适配器配置持有，训练脚本与目录名无关。

## 二、统一接口（保持不变的部分）

```python
# experiments/common/temporal/adapters.py【拟】
class DataAdapter(ABC):
    split_of: dict          # seg_key -> train/val/test
    def single_frames(self, split) -> Iterable[Sample]:   # 单帧模式
    def windows(self, split)   -> Iterable[Window]:        # 连续帧模式: 一段输出若干窗口
    @property
    def metrics_summary(self) -> dict                       # 各 split 窗口数/正负/段数(核对用)

@dataclass
class Sample:    seg_key: str; feats: np.ndarray  # [D]          单帧:1帧特征
@dataclass
class Window:    seg_key: str; feats: np.ndarray  # [K,D]; label: int; mean_logit: float
```

- `windows(split)` 内部走「段→窗口→帧」三步，全部由采样策略决定窗口数和帧数。
- 训练脚本（如 `train_temporal.py`）只用 `windows("train")` / `windows("val")`，不碰路径、不碰 K/步长/段上限。

## 三、采样策略 = 可插拔配置（开闭的"扩展点"）

把"窗口怎么切、每段几帧"抽成策略对象，默认实现 = 当前试点 (`EXP006WindowPolicy`)；换策略（如正式全训的 `段间严格等权策`、`d3 纳入策`）只需加新策略，不改训练脚本。

```python
class WindowPolicy(ABC):
    K: int = 16              # 窗口帧长
    stride: int = 8          # 窗口步长
    max_win_per_seg: int = 8 # 每段窗口上限
    min_frames: int = 16     # 短段加密目标(方案A:至少能出1个窗口)
    def window_starts(self, n_frames): ...   # 段内起点集合(当前: linspace均匀取≤8)
    def class_weight(self, n_pos, n_neg): ... # 类权重 负/正
```

**顺带把方案 A 落进策略**：`min_frames=16`，对帧不足段的加密 = 兜底采样打到 ≥16（短段补足），由 `VideoWindowAdapter` 在加载层执行，训练脚本无感知。
