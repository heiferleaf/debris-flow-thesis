# 为什么审计画面正常，训练片段仍可能无效

更新：2026-11-08。结论基于现有索引、帧、输入指纹、代码与实际回执；本轮没有重新解码全部原片或删除审计大图。

## 1. 两套图像原本服务不同用途

审计台通常每约2秒显示一张较大图，帮助人辨认流态和划时间区间。当前模型则在约3秒内取16个不同的真实帧，最后得到RGB112输入。16张相邻审计图通常跨约30秒，不能不加说明就代替3秒训练输入。

审计图与训练图不是同一批文件，但并非永远互不相关：早期EXP-006确实读取过审计来源图，实际日志为11,944帧、读图失败0；现在EXP-017/022的RGB路径改用256中间件及独立PTS采样。保留旧审计图也有历史复现原因，不能把“当前不直接读”理解为全部无用。

当前路径为：原视频→256×256解码中间件及逐帧时间/质量表→在真实时间支持内选16帧→JPEG95及RGB112转换→模型。审计路径的OpenCV显示时间与中间件PTS不保证天然逐帧等同，需要映射。像素验收、时间对齐和标签正确性是三个不同检查。

本轮只对1-16局部seek解码1030–1045秒：首张JPEG为灰，随后画面恢复。它说明局部解码/参考帧恢复本身也可能产生异常，不能据一张灰图就断言原始采集全损坏。原片画面时钟与审计秒数的对应仍有约一帧级差异；局部probe没有重建全库时间轴，也没有证明旧QC保护范围都合理。

## 2. 为什么看到的多数都是好画面

不是简单地说“坏帧刚好藏在两秒之间”。已有直接证据是：

- 1-74当前索引167张，原编号0–274中的108个缺口，全部命中早期灰帧清单。
- 1-112当前154张，原编号0–272中的119个缺口也全部命中该清单。历史删除执行器回执并未全部恢复，但当前缺口与清单的逐项吻合可核实。
- 时间轴通常只挑最多120张缩略图。1-44约531.43秒的灰图仍存在，却没有出现在这条稀疏缩略条中。
- 即使一张图正常，片段前后可能有cut、坏图、时间回退或空洞。模型需要整个连续支持有效，不能把断口两边的好图拼起来。

因此，审计页面显示正常、缓存图可读、连续16帧支持有效、标签正确，彼此不能相互替代。

## 3. 1-112的具体例子

现有质量表有10,573帧，其中4,719帧灰度标准差低于20；旧禁止范围和保护邻域共覆盖7,836帧，额外包含3,117个自身达到该阈值的帧。低纹理阈值只是启发式，不等于这些帧逐张都被人工认证为纯灰。

保护邻域会使剩余连续段变短。一个净区为5.80–6.65秒，只有0.85秒：里面能留下一张好审计图，却不够一个3秒输入。最长净区30.80–36.75秒，共5.95秒，能取3秒、不能取7.5秒。现有规则下仍有264个合法3秒候选，不是整条视频不能训练。

保护区额外剔除了多少帧可以量化，但目前没有足够视觉证据证明这些保护全属错误。后续若缩小保护必须以实际相邻帧和时间坐标为依据，不能为了增加窗口数直接取消。

旧实验“22条不足48个长窗”与本例要分开。当前150池已取消每视频必须48窗，按视频×类别每轮上限4窗，不要求补满。旧失败名单不能拿来描述当前3秒输入的可用性。

## 4. 100多GB来自哪里

11月7日存储快照为106,819,600,382逻辑字节，约106.82GB；它包含审计JPEG、缩略图、总览和CSV，不能把184,605个目录文件全当成独立帧。四套索引合计121,923条，其中v1为74,020、v3为240、v4为26,099、v5为21,564。审计范围还包含部分未进入150池的保留视频。

主要体积是v4约70.68GB、v5约20.42GB、v1约15.53GB。上游抽帧的尺寸不统一，确实造成不必要的存储负担：

- 1-16：原片3840×2160，审计图已缩为960×540。
- 4-08：原片和审计图均2560×1440。
- 5-01：原片5120×1400，审计图1920×525。

因此此前统一称“107GB原尺寸帧”不准确；其中较大的v4图没有统一缩成适合日常浏览的预览。大文件体积也不等于同等数量的独立或连续训练信息。

## 5. 维护决定

**2026-11-08已完成v4实际瘦身。** 26,099张审计JPEG的数量、文件名和索引不变，合计70,488,022,389→14,778,814,176字节，减少55,709,208,213逻辑字节。2,235张实际历史训练或复核引用图保留原字节，逐张SHA256一致；其余23,864张等比压到长边1280、JPEG85。原视频及当前训练缓存不在处理范围。审计服务已实际返回1280×720预览。

本次不是声称从原片能逐字节再现全部旧JPEG，故历史直接像素引用被单独保护。保护来源、逐文件前后哈希/尺寸和完成回执在`data/metadata/audit-cache-compaction/20261108-v4/`。C盘空闲从50,289,238,016增到108,842,639,360字节；期间可能有其它磁盘活动，不把空闲差完全归因本工具。

“每2秒都是好图”也并非事实：1-44的531.43秒审计图仍有明显灰损，原文件`video1_segment/frames/v1_44_frame_000265_t531s.jpg`已实际查看。1-74缺108个编号、1-112缺119个编号，均与历史灰帧清单逐项吻合；服务加载索引时还会跳过不存在的JPEG。灰图过滤加稀疏缩略条共同影响了用户看到的画面，不是巧合。

保留原片、标注、索引、坐标/QC、实际训练引用和必要的旧实验像素证据。日常页面优先按需生成缩略图及中等尺寸预览；大图只在需要看细节时读取。新增预览不再默认保存全分辨率帧，也不为多个入口复制大媒体。

上述v4已按历史引用保护实施。其它审计大JPEG仍按同一原则处理，不能仅因当前模型用RGB112就全删，也不能无记录覆盖历史直接像素证据。

较新的`data/metadata/cache-retirement/cleanup-result-20261107.json`已经确认58,946个可再生缓存文件删除成功，逻辑字节1,594,529,830、失败0、raw与TXT保留。回执中的C盘空闲实际增加约0.454GB，不能保证释放量等于逻辑字节。更早“审批拒绝”的过程记录不是当前状态，本轮已更正数据清单入口。
